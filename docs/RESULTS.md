## Interpretation

The evaluation is a single deterministic day on the same price profile used for training. It has no held-out real data, uncertainty interval, or multi-seed comparison. The always-on comparator is intentionally wasteful. Savings should be described as savings against that simulated baseline.

## Visualization caveats

- The training-loss plot can substitute a simulated curve when logged loss is unavailable. A displayed curve should be checked against its legend before being treated as observed training evidence.
- Indoor temperature is generated by an illustrative random process and is not part of the environment or reward.
- Replay hourly rewards omit the off-peak bonus and end-of-day penalty, so they do not show the complete training reward.
- The comprehensive power plot uses all six appliances on as its baseline, rather than the fixed fan/light schedules used for baseline cost evaluation.
- The notebook comfort scenario subclass retains the original comfort penalty, then adds the custom-window penalty; this is not a clean replacement of the original window.
- Uniform price multipliers preserve normalized price observations, so the current policy does not learn new schedules from the multiplier control.

## Reproduction

Run the notebook in order with the notebook requirements installed and writable output paths configured. The dashboard trains separately with several default DQN hyperparameters, so its displayed values need not match the notebook. Record Python and all package versions, hardware, seed, tariff, training settings, and evaluated schedules when reporting a new result.
